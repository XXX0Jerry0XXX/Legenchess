# 传奇棋 8×12：PPO 实现与后续方案

当前版本已实现无界面训练环境、共享完整决策、PPO 训练器、历史快照对手池和网页推理。训练与复现命令见 [training/README.md](../../training/README.md)。本轮实际成绩单独记录在训练结果中，不用训练奖励替代独立棋力评测。

## 第一版的选择

第一版采用合法候选动作评分的 PPO。每步先枚举所有合法完整决策，网络对候选打分并采样；批训练时屏蔽补齐的无效位置。这样可以完整支持技能组合，也避免第一版就引入多阶段策略的联合概率和回溯约束。后续候选数量成为瓶颈时，再改为分层选源棋子、行动和目标。

PPO 的裁剪策略梯度目标参考[原始论文](https://arxiv.org/abs/1707.06347)。合法动作掩码的研究说明了这类约束在策略梯度中的作用；本项目采用实际规则枚举合法集合。[动作掩码论文](https://arxiv.org/abs/2006.14171)

第一版网络只有 16,258 个参数，导出 JSON 后用同构 JavaScript MLP 在 Worker 中推理。这样无需额外推理服务或框架。更大模型可再导出 ONNX；这是后续选项。[ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/)

## 实际模块

| 模块 | 责任 |
| --- | --- |
| `src/game/decisions.ts` | 完整合法决策、候选校验及转换为 reducer 的 `Action[]` |
| `src/game/rules.ts` | 共享伤害、死亡、移动和回合结算 |
| `src/game/rl/features.ts` | 双方棋子/全局特征、完整动作特征和基准策略特征 |
| `src/game/rl/environment.ts` | 固定种子开局、训练课程、对手回合、虚拟时钟与终局 |
| `scripts/rl-server.ts` | 长驻 Node JSONL 环境接口，量化二进制特征传输 |
| `training/ppo.py` | PyTorch PPO、GAE、快照池、检查点、续训及独立评测 |
| `src/game/rl/policy.ts` | 导出网络的 JavaScript 推理与版本校验 |
| `src/game/ai/ppo.worker.ts` | 网页模型加载和完整动作推理 |
| `src/game/ai/ppoClient.ts` | 带请求编号、超时和错误处理的 Worker 客户端 |

模型只对应内置六类棋子与当前规则版本。自定义 Mod 需要对应的特征、动作与模型版本，不能直接把旧权重当作通用 Mod AI。

## 规则一致性

训练直接调用网页使用的 TypeScript reducer；没有维护另一份 Python 战斗规则。训练前已合并重复伤害/死亡/回合逻辑，并修正：

- 新手击杀时先处理转职，即使反击伤害致命也能转职后继续，再处理目标死亡和胜负。
- 刺客免费次数在本回合结束时清理，AP 为零时仍可使用尚未消耗的免费动作。
- 共享完整决策层校验阶段、职业、范围、AP、目标数量、复活窗口与待转职状态。
- 终局用 `winner !== null` 判定，玩家 0 获胜不会被真假值判断漏掉；待转职时不能结束回合。

刺客和牧师使用专门的 reducer 分支；没有调用技能注册表中不产生实际效果的占位动作。法师完整决策枚举所有合法的 1～3 个不重复目标组合，整组只扣一次 2 AP。牧师枚举所有合法的复活对象和备战区空格，保留转职形态及会长 AP 奖励。

## 状态和策略网络

统一为己方在下方的视角；源、目标和方向特征同步变换。矩形棋盘可以做左右镜像，不能做 90° 旋转。

观测为 16 个全局量与双方各 16 个棋子的 18 维特征，共 592 维。全局量包括 AP、先后手、回合、双方数量/血量/子力、会长状态、剩余时间和待转职标记；棋子特征包括类型、坐标、HP/maxHP/ATK、免费标记、死亡状态、死亡窗口和待转职身份。

每枚棋子通过共享 MLP，再对双方分别做均值与最大值池化，避免依赖时间戳 ID 或槽位排列。32 维状态表示同时供价值头和策略使用。每项候选有 96 维特征，编码动作类型、源/目标及技能参数；策略结合候选表示与状态表示输出分类分布。

一次训练步是一项完整游戏决策：移动、攻击、技能、免费动作、转职或结束回合。选择棋子、切模式和点击确认都不额外产生训练步。网络初始参数随机，学习方策略没有写死的启发式分数，也没有模仿训练目标；单独的战术 AI 只充当训练对手和评测基准。

## 训练回报和自博弈

每局固定学习方，学习方一步之后，环境自动运行对手直到再次轮到学习方。由此连续观测保持同一评价视角，AP 连动不会让价值每步错误取负。

真实终局奖励为胜 +1、负 −1、平 0。初期增加系数 0.2 的势函数塑形：`r′ = r + β(γΦ(s′) − Φ(s))`，Φ 为有界、同一方视角的子力与血量差，终局取零。没有按复活次数或每次攻击直接发奖励，避免刷分循环。

训练前 32768 步使用较少存活棋子的残局课程，随后 75% 完整开局、25% 残局。完整开局双方各 16 子，采用固定种子的独立随机合法布阵。布阵策略尚未训练；AI 不会读取对手隐藏布局再决定己方布阵。

历史快照可用后，对手混合为约 25% 快照、50% 新增战术 AI、25% 随机合法策略。快照最多保留 4 个，每局固定一个对手网络，正在进行的棋局不热更新对手权重。不要把这个快照池称为已经验证收敛的联赛系统。

每方仍为 1500 秒，训练以每项完整决策消耗 10 秒虚拟思考时间近似真实计时，时间耗尽按剩余子数结算。网页采用真实时钟。达到采样上限的对局标记为截断，不伪造平局，并从最后的非终局状态 bootstrap。

## 独立评测

评测只使用完整 8×12 开局，每个对手至少 200 局，100 组种子交换执棋方。使用与训练分开的种子，对随机初始网络和已训练网络使用相同测试设置。报告胜/负/真实平局、得分、完成率、截断率和胜率区间。

初级 AI、游戏原 expert AI、新增战术 AI 分别报告；旧 expert 的一步评价较弱，常提前结束回合，战胜它不能代表战胜真人。默认评测采用贪心选择，与网页一致。虚拟耗时版本的成绩也不能直接外推为真实 25 分钟比赛成绩。

## 后续提升

1. 在独立验证集上比较更长训练、不同快照比例和较慢的虚拟时钟，保留新的最终测试集。
2. 增加针对反击、会长保护、法师群攻、刺客连击和复活落点的战术题，并请人试玩。
3. 若候选枚举成为瓶颈，改为条件合法掩码的分层策略；保存整项决策的联合对数概率，保持一次环境步只结算一项完整行动。
4. 再比较策略价值网络配合 PUCT/MCTS 的实际收益。搜索状态必须包含 AP、免费标记、死亡窗口和待转职信息；同一方连续行动时不翻转价值，只有评价方切换时才改变符号。[AlphaZero 原始论文](https://arxiv.org/abs/1712.01815)
5. 布阵学习单独建模，只提供己方信息，避免隐藏信息泄漏。
